## Project summary

**Breathway** (`be.melxaco.breathway`) is a Garmin Connect IQ **watch app**
written in Monkey C. It guides the user through a breathing exercise (default:
box breathing, 4-1-6-1 — 4s in, 1s hold, 6s out, 1s hold) with an animated
circle and phase labels.

- Manifest app id: `6067a557-3b4a-4abb-a98b-e0a0bc175c32`
- Entry point: `BreathwayApp` (`source/BreathwayApp.mc`)
- Primary view: `BreathwayView` (`source/BreathwayView.mc`)
- Input delegate: `BreathwayDelegate` (`source/BreathwayDelegate.mc`)
- Initial target devices: fenix7, fenix7s, fr265, fr965, fenix8solar51mm
  (semi-round Fenix/Forerunner family). Default simulator/debug target is
  `fenix7s` (see `.vscode/launch.json`). Add more in `manifest.xml` under
  `<iq:products>` and, if resources need to diverge, in `monkey.jungle`.

## Toolchain

This project targets the **Garmin Connect IQ SDK** (Monkey C language, SDK
manager `sdkmanager`, compiler `monkeyc`, simulator `connectiq`/`monkeydo`).
The SDK itself is **not part of this repo** and must be installed separately
(see README.md). Do not attempt to install or download the Connect IQ SDK
automatically — ask the user if it's missing.

Key files:
- `manifest.xml` — app metadata, id, target devices, permissions.
- `monkey.jungle` — build configuration (source/resource path mapping per
  device group).
- `source/**/*.mc` — Monkey C source.
- `resources/**` — strings, drawables, layouts (XML), loaded via `Rez.*`.
- `test/**/*.mc` — unit tests using the `(:test)` annotation and
  `Toybox.Test.Logger`.

## Build & test commands

Once the SDK is installed and `monkeyc`/`monkeydo` are on `PATH` (or full
paths are known), typical commands are:

```bash
# Compile
monkeyc -f monkey.jungle -d fenix7s -o bin/breathway.prg -y developer_key

# Run in simulator (start the simulator app first, then):
monkeydo bin/breathway.prg fenix7s

# Compile & run unit tests
monkeyc -f monkey.jungle -d fenix7s -o bin/breathway-test.prg -y developer_key --unit-test
monkeydo bin/breathway-test.prg fenix7s -t
```

Prefer using the **Monkey C VS Code extension** commands ("Build Current
Project", "Run Current Project in Simulator", "Run Tests") when working
interactively — `.vscode/launch.json` and `.vscode/settings.json` are
pre-configured for it.

There is no separate linter; rely on the extension's built-in Monkey C type
checker (`monkeyC.typeCheckLevel` in `.vscode/settings.json`, currently
`Informative`). Treat new type-checker warnings introduced by your changes as
something to fix, not ignore.

## Conventions

- One public class per file; file name matches the class name
  (`BreathwayView.mc` → `class BreathwayView`).
- Use explicit `Toybox.*` imports at the top of each file rather than
  wildcard imports.
- Prefer typed signatures (`as Type`) on all function parameters and return
  values — the project is written for Monkey C's type-checker, not legacy
  untyped API.
- Keep drawing/update logic in `View.onUpdate`; keep input handling in the
  `BehaviorDelegate`. Avoid business logic (breathing-phase timing, pattern
  definitions) living only inside the view — extract into plain classes as
  the app grows so it can be unit tested (see `test/BreathwayTests.mc`).
- Never commit `developer_key` (or `developer_key.der`) or any `bin/`/`gen/`
  build output (already covered by `.gitignore`).
- Resource strings go in `resources/strings/strings.xml` and are referenced
  as `@Strings.Name`; drawables in `resources/drawables/drawables.xml` as
  `@Drawables.Name`.

## What to do when the SDK isn't installed

If a task requires actually compiling/running the app and the Connect IQ SDK
is not present, stop and ask the user rather than trying to fetch/install it
yourself — SDK distribution requires accepting Garmin's license via
`sdkmanager` interactively.

## Commit conventions

This repo uses [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/)
(`type(scope): subject`, e.g. `feat(view): add pause/resume on select`,
`fix(delegate): handle back button on round devices`). Common types used
here: `feat`, `fix`, `chore`, `docs`, `test`, `refactor`. AI-generated
scaffolding/config commits use `chore(scaffold): ...` so they're easy to spot
in history; keep using that convention for similar broad, generated changes.
